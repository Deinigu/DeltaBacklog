# Changelog

All notable changes to DeltaBacklog are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) once it has a first release. Dates are when the pull request was merged. Pull request numbers before 2026-10-10 refer to the earlier private repository.

## [Unreleased]

### Added

- **Preferred stores on Deals**: rank the shops you like (for example Steam over Microsoft Store or Epic) from the **i** panel, **Preferred stores**. The price shown, the sort and the price alerts (and the Telegram messages) follow the highest-ranked shop that sells the game, not the cheapest offer; a historical low that exists only at a lower-ranked shop does not alert. A clearly cheaper offer at another shop (more than a threshold you set, 15% by default) appears as a small hint such as *€9.99 at Epic Game Store*. An empty list keeps the old behaviour. One extra batched request (`POST /games/prices/v3`, 200 games) per refresh, none per game. Migration 022 (`alt_shop`, `alt_price`, `alt_url` on `deal_price` and `wish_price`; the ranking is in `setting`). New endpoints `GET` / `PUT /api/deals/stores` and `GET /api/deals/shops`; `GET /api/deals` also answers `stores`.
- **A denser Deals page**: one compact row per game (SteamDB style) with a small picture, the name and tags, a green discount box, the price and the lowest ever, and a sortable table with column headers on a PC; a tap on a row opens an action sheet (View deal, Open game / Steam page, Add to library, Mute, Hide); a one-line toolbar (Library / Wishlist, refresh with the time it was checked, country) and filter chips in one scrolling row.
- **Pictures for your wishlist games on Deals**: Steam's small capsule art, downloaded once during a refresh (a few batched requests, only for games without one) and served from your own server. Library games with no cover but a Steam link get the same picture; pictures of games that left your wishlist are removed.
- **Deals**: a **Deals** page (`#/deals`) with the best price right now and the historical low of the games you don't own and haven't played yet, from IsThereAnyDeal (ITAD). A game is listed when it is in Backlog or Up next, has no years played and its ownership is Borrowed, Family Share, Nope or empty (Owned, Free to play and Pirated games are not). Games on sale come first (biggest cut), then games at or near their low, with **Historical low** / **Near low (within 10%)** badges, the shop, the regular price, the cut, the end date and a **View deal** link. Filter chips, three sorts, **Hide** (with Undo) and a **Hidden (N)** list, a *Last checked* note and a country setting (default `ES`). A game's details show the same price line, with **Wrong game?** / **Pick the game** to fix a match (by Steam link, else exact title). Prices are read only by **Refresh prices** (a background run with progress, 50 games per request, stops with what it stored on a 429), never on a page load. Needs `ITAD_API_KEY`. Migrations 016 and 019 (`setting`, `deal_match`, `deal_price`, `deal_hidden`). New endpoints `GET /api/deals`, `POST /api/deals/refresh`, `GET /api/deals/search`, `PUT /api/deals/country`, `PUT` / `DELETE /api/deals/hidden/{id}`, `PUT /api/games/{id}/deal-match`.
- **Deals price alerts**: a game gets an alert when its best price, on sale, is at or below its **historical low** or its **lowest price of the last 2 years** (no target prices; the two-year low comes from ITAD's price history, one call per game, kept for a week). An **Alerts** chip, **Alert: ...** lines on rows and in the game's **Price** details, **New** tags, a count badge on **Deals** in the More menu and the sidebar until you open it, and **Mute** / **Price alerts: on / off** per game. You are told once per deal: again only at a lower price or after 30 days. `deltabacklog deals-check` refreshes the prices (same rules as **Refresh prices**) and applies the rule; `deploy/` installs a daily systemd timer for it (`deltabacklog-deals.timer`, 08:00 with a random delay) that never runs together with the page's refresh (a lock row in the database; the page answers 409 meanwhile). Optional **Telegram** messages (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, kept by `deploy.sh` and `install.sh`): one message per game, or one list for more than three; an alert that could not be sent is tried again at the next check; a **Send test message** button appears on Deals when it is set up. Migration 020 (`deal_alert`, `deal_price.low2y_price`, `low2y_checked_at`). New endpoints `PUT` / `DELETE /api/deals/muted/{id}`, `POST /api/deals/alerts/seen`, `POST /api/deals/telegram-test`; `GET /api/deals` also answers `alerts`, `muted`, `unseen` and `telegram`.
- **Your Steam wishlist on Deals**: set `STEAM_ID` (your 17-digit SteamID64; no Steam key, the wishlist must be public) and Deals gets a **Library / Wishlist** switch. A wishlist row has the same price row, alerts (Telegram messages tagged *💙 Wishlist*), **Mute** and **Hide** as a library row, plus **Add to library**, which opens the add form with the title; once the game is in the library the entry disappears. Games you buy leave your Steam wishlist and so Deals on the next refresh; a private or empty wishlist is explained and never wipes the list. **This is not the old Wishlist status** (removed in migration 018): wishlist games are not library games and never appear in the Library, views, stats or series. The wishlist is read from Steam only by **Refresh prices** and `deals-check`, and games are matched to ITAD by Steam app id (one lookup each, once). Migration 021 (`wish_item`, `wish_price`). `GET /api/deals` answers `wishlist` (`null` without `STEAM_ID`); new endpoints `PUT` / `DELETE /api/deals/wishlist/{appid}/hidden` and `/muted`.
- **A visual Series page**: a grid of series tiles (a fan of the series' posters, progress bar, *2/4 finished*); a tile opens the series on its own route (`#/series/<name>`) as a poster shelf in release order, with ✓ / ▶ marks for finished and played games.
- **Games you do not have yet, on the Series page**: the games of the IGDB collection behind each series that are not in the library appear in release order as greyed "Not in your library" posters with **Add** (the add form, pre-filled from IGDB with your own series name) and **Hide** (with Undo and a **Hidden (n)** list). Only real games (main games, standalone expansions, remakes, remasters); a game counts as owned with its other IGDB entries (original, expanded edition, remaster, port). The collection of a series comes from its linked games. The lists and their small posters are cached on the server (migration 013) and read only by **Refresh from IGDB** or `sync-igdb --enrich`, never on a page load. A **Not in your library** filter. New endpoints `GET /api/series/missing`, `POST /api/series/refresh`, `/api/series/hide`, `/api/series/unhide` and `GET /api/igdb/{id}`.
- **Upcoming releases**: an **Upcoming** page (`#/upcoming`) with the new games of your series that you do not have and that are not out yet, grouped by month (then Later / TBA), with poster, date, platforms and series, **Add** and **Hide**, and a **Recently released** section (last 60 days). IGDB's first release date is stored with its precision (day, month, quarter or year; migration 014), so "2027" is never shown as a day. Filled on add and relink, by `sync-igdb --enrich` and by **Refresh from IGDB**.
- **Similar games**: a **Similar games** page (`#/similar`) with the games IGDB lists as similar to the games you finished or favourited and that you do not have, ranked by how many of your games suggest them, each with *Because you played X, Y and Z*, **Add** and **Hide** (with Undo and a **Hidden** list). Another version of a game you own (remaster, port) is left out, a remake or standalone expansion is not. A finished or favourite game's details show a small *Similar games* row. Cached in the database (migration 015) and read from IGDB only by **Refresh from IGDB** and `sync-igdb --enrich`.
- **Hidden page**: a **Hidden** page (`#/hidden`) with everything you hid on **Deals**, **Similar games** and **Series** (also what you hid on Upcoming), each row with its cover, the date it was hidden and **Show again** (with Undo). Read from the database only. New endpoint `GET /api/hidden`; no migration.
- **Needs attention page** (`#/attention`): the games that need a fix in collapsible groups with counts, each row with a one-tap fix: not linked to IGDB, uncertain IGDB match, no cover, no poster or only a crop of the cover, no time to beat (Backlog, Up next, Playing), no platform, no release year, no ownership and no genres. **Ignore** hides a game from one list (stored in `setting`; `GET /api/attention/ignored`, `POST /api/attention/ignore`; no migration). Computed in the browser from the loaded games, so opening it makes no IGDB request. `GET /api/games` also carries `poster_src`, `poster_user` and `igdb_not_found`.
- **Find times for all**: the *No time to beat* group of Needs attention can search HowLongToBeat for all its games in one background run (progress, **Stop**, one search at a time about a second apart). It saves a time only for a confident match (same normalised title, same release year when both are known, a single such game); the others stay in the group marked *Needs a manual pick*. Games that already have a time and ignored games are never touched. New endpoints `GET /api/ttb/sync`, `POST /api/ttb/sync`, `POST /api/ttb/sync/cancel`; `hltb.Confident`.
- **Update the details after relinking**: when a game gets a new IGDB link (the Link IGDB screen, **Fill from IGDB…** or Needs attention) a card asks *Update details from it?* with **Fill empty fields** (default) and **Replace all…** (shows *field: old → new* first), then an **Undo** message. It reuses the `sync-igdb --enrich` fill code for one game. Status, ownership, notes, years played, covers, a chosen poster and times set by hand or from HowLongToBeat are never touched. New endpoint `POST /api/games/{id}/igdb-details` (`apply: false` previews).
- **Upload your own cover or poster**: **Upload from device** in the cover and poster pickers (the photo picker or camera on a phone). Photos are shrunk and turned upright in the browser before they are sent; the server judges the file's bytes (up to 10 MB and 40 megapixels, within the decode budget, EXIF orientation applied) with clear messages for a wrong type, a file that is too big or a damaged one. An uploaded poster is the user's (`poster_user`) and is never replaced automatically. New endpoints `POST /api/games/{id}/cover/upload` and `POST /api/games/{id}/poster/upload`.
- **The poster follows the IGDB link**: linking a game to a different IGDB game fetches the new game's poster in the background (IGDB, then SteamGridDB, then the crop) unless the poster is the user's, retried when IGDB fails for now; clearing the link leaves it alone. Every automatic poster write is dropped if the game's IGDB link changed meanwhile.
- **Choose the poster** (the portrait picture of the rankings and the tier list PNG): **Change poster** in a game's details and in the bar of a ranking board. The sheet offers the IGDB cover and several SteamGridDB portrait grids, a pasted image link, **Crop of the wide cover** and **Fetch automatically again**; if SteamGridDB cannot be reached the IGDB options still appear. A chosen poster is never replaced by the queue or `fetch-posters --upgrade` (migration 011, `game.poster_user`). New endpoint `POST /api/games/{id}/poster`; `GET /api/covers/search` takes `shape=poster`.
- **Time to beat from HowLongToBeat, editable**: the game details have a **Time to beat** block with three tiles (Main story, Main + extras, Completionist), a source note (*from IGDB*, *from HowLongToBeat* or *set by you*), **Edit times** (hours, `7h30` or `45m`) and **Get from HowLongToBeat**. Times you set or took from HowLongToBeat are never overwritten by the IGDB enrichment or cleared by relinking. `GET /api/hltb/search`, `ttb_*` fields on `PATCH` / `POST /api/games`, `game.time_to_beat_src` (migration 012).
- **Filter and sort by time to beat**: a **Time to beat** block in the filters (quick ranges, your own From/Under in hours, "No time known", which estimate to use), in the Library, saved views and the rankings' game picker; a **Time to beat** sort and table column. It replaces the *Short game (under 10 h)* switch: saved views and links that used it now read *Time to beat under 10 h*.
- **Add a game with every field**: the add form also has years played, played with, favorite, VR, 100% completed and notes (the less common ones under "More details"). `POST /api/games` now stores favorite, VR and 100% on create.
- **Screenshots**: upload several pictures per game from a phone or computer (drag and drop on a PC), thumbnail grid, full-screen viewer with swipe, captions, reordering, download of the original and delete with undo. Originals are stored untouched (JPEG, PNG, WebP, content-checked) next to a generated thumbnail (migration 009).
- **Screenshots page** (More menu on a phone, sidebar on a PC): every screenshot of every game in one gallery, grouped by game or newest first, with search by game or caption, a year filter, lazy thumbnails and "Show more" paging. The viewer goes through all matching pictures across games and can open the game. New endpoint `GET /api/screenshots`.
- **`SCREENSHOTS_DIR`** (and `SCREENSHOT_MAX_MB`, `SCREENSHOT_REQUEST_MAX_MB`): screenshots can live on an external drive. The app never creates that folder, so an unmounted drive cannot fill the SD card; uploads then say "screenshot storage not available". The nightly backup also copies new screenshots incrementally (`deltabacklog backup-screenshots`), only while the backup disk keeps `SHOTS_MIN_FREE_GB` free, and saves the database copy on the external drive too; `install.sh` writes the systemd drop-ins for the drive.
- **Rankings** replace the per-year tier list: TierMaker-style custom rankings with as many tiers as you want, your own labels and colours, a dark board of big portrait posters, drag and drop (touch: long press), tap-to-select with buttons, keyboard moves, S/M/L tile size and PNG export. Add any set of games from the whole library with search and filters. Year in review has a "Rank this year" button. Your old tier lists became rankings called "Tier list <year>" (migration 010; the old tables stay unused).
- **Posters**: portrait box art for the rankings, made once per game in the background (IGDB cover, else a SteamGridDB 600x900 grid, else a crop of the wide cover). `deltabacklog fetch-posters [--dry-run] [--limit N] [--upgrade]` makes them all at once.
- **`PUBLIC_NAME=off`** in `/etc/deltabacklog.env`: `install.sh` then disables and stops `deltabacklog-name.service` (no `deltabacklog.local`, no port 80 rules), for an app reached only through a reverse proxy (with `LISTEN_ADDR=127.0.0.1:8081`). `deploy.sh --env` keeps `ALLOWED_HOSTS`, `PUBLIC_NAME` (and, with `PUBLIC_NAME=off`, `LISTEN_ADDR`) from the installed settings, as it keeps `SCREENSHOTS_DIR`, `STEAM_ID` and the Telegram settings.
- **Works under a sub-path behind a reverse proxy** (for example `http://<pi-name>.local/backlog/`, with the proxy stripping `/backlog`), as well as at the root, with no setting: every URL the app uses (API, covers, screenshots, the service worker and its caches, the web app manifest) is relative to the page. The proxy's host name goes in `ALLOWED_HOSTS`.

### Changed

- Telegram lists of more than three price alerts are easier to read: each game on two lines with the store that has the price, a blank line between games, and the library and the wishlist under their own headings.
- **Nicer Telegram messages**: price alerts use Telegram's HTML formatting: a 🔥 / 📉 headline, the bold title, the price with the regular price struck through, the cut, the shop, the low to compare with and a *View deal* link; wishlist games are tagged 💙 and show a large preview of their Steam page; lists of more than three games have a header and one compact line per game. The test message says DeltaBacklog is connected and shows an example alert. Titles and shops are escaped.
- **A fuller Stats page**: summary tiles and jump buttons; estimated hours spent on finished games (by year, genre and platform) and left in Up next and Backlog (with your own hours a week); games played and finished per year; finished against dropped by genre and platform (groups of 5+); the 10 shortest games waiting; library by ownership, platform and decade; series completed. Every estimate says how many games it rests on.
- **Default order is now Status, then Title** (it was Status, Manual order, Title). The starter *Up next* and *Playing now* views set *Manual order* explicitly and are unchanged; add *Manual order* as a sort level to any view that should show your ranking. No migration.
- **Usability pass** (the look is unchanged):
  - The **+** button is shown only on the Library, saved views and shelves (the `n` key still adds a game anywhere); on a PC its place is kept clear of the last row.
  - Library and views on a phone: the title has its own row, the buttons under it are labelled (*Surprise me*, *Table*, *Reorder*, *Views*), and only the search row stays pinned while scrolling.
  - The reorder handle and its arrows are 44px wide on phones; the strips of active filters and years fade at the edge to show they scroll, and the current year is centred.
  - Rankings: no empty gap under the back link; unusable arrows are hidden, **Delete** is red and apart from Rename and Duplicate.
  - Series: the filters above the tiles take fewer rows; a series with many games you do not have lists the first six, then **Show all**. A tile shows the portrait poster, or the wide cover whole instead of cropping it.
  - Upcoming: **Add** and **Hide** sit under the text on phones. Similar no longer says "Press Refresh" twice. Years: a zero tile is quiet instead of as loud as a real number. Empty states are one short sentence with their button. Dates on the Series page use the English format like the other pages.
- The years-played picker offers the years from the earliest year in your library to this year (the last 10 while the library has none) instead of going back to 1990; older years can still be typed (a year outside 1970-2100 now says so). The add form asks before discarding details you typed.
- **Documentation pass**: the user manual and the developer manual were reorganised into one coherent set (one "Setting up keys" section, a "Refresh buttons" overview, the pages in the order the app shows them, updated troubleshooting, and the migrations, API, background jobs, modules and deploy sections brought up to date), the README and `.env.example` list every feature and setting, and every screenshot is regenerated from the demo library in the dark theme.
- The repository is now a public showcase, not a community project: README status note and "How this was built" section, CONTRIBUTING explains that contributions are not accepted, and the code of conduct, issue forms and pull request template were removed. Dependabot runs monthly with grouped updates.
- Deploys are stamped with a version from `git describe`; idle connections are closed after 2 minutes; CI fails on unformatted Go code.

### Removed

- **The old Wishlist status and Steam sync.** The *Wishlist* status, the **Steam** page and `deltabacklog sync-steam` are gone, with the hours played (the *12 h of ~15 h* line, the **Played** column and sort) and `STEAM_API_KEY`. Migration 018 moves any Wishlist game to Backlog, drops the Steam tables and the stored hours, and removes the Wishlist status and any Steam-hours sort from saved views. Delete `STEAM_API_KEY` from `/etc/deltabacklog.env` (and revoke the Steam Web API key if you do not want it). `STEAM_ID` is read again, but only for the wishlist section of Deals (see Added). **Upcoming** lists only the new games of your series that you do not have; Similar games has no *Wishlist* button.

### Fixed

- Deals on a PC: the table only shows *Ends* and *Added* from 1440px wide, so game names are no longer cut short at 1280px; September dates read "Sep", like the other months.
- **Wishlist prices never arrived (IsThereAnyDeal rate limit).** The Steam wishlist was matched with one IsThereAnyDeal request per game (about 125), which used up the key's rate limit before any wishlist price was read: the first Refresh on the Pi priced none. Games are now matched in bulk (`POST /lookup/id/shop/61/v1`, up to 200 per request) and named by Steam in batches of 100 (`IStoreBrowseService/GetItems`), so 130 games cost about 6 requests the first time and, afterwards, only the 3 or so price requests (no matching or naming requests). A rate limit during matching no longer skips pricing (everything matched is priced, the rest waits for the next run, and the report says *Wishlist: 96 of 124 priced; the rest next run*), and the two-year-low history reads are capped at 15 per run so they never starve the price steps. Any error while matching (not only a rate limit) still lets the matched games be priced and is reported, a short `Retry-After` (15 s or less, in seconds or as an HTTP date) is now waited out once before the request is sent again, and the report no longer says "the rest next run" when games only turned out to be in the library. No migration.
- The **Hidden** page names a hidden series game's series as you wrote it (*Ace Attorney*), not the lower-cased key (*ace attorney*).
- The "read on" dates of the Series, Upcoming and Similar games pages and the "Hidden on" dates now use the same English format as the rest of the app (*3 Nov 2026*), not the browser's (*03/11/2026*).
- An empty value in `.env` (such as `GOMEMLIMIT=`, as in `.env.example`) is skipped instead of logging "ignoring GOMEMLIMIT" at start-up.
- IGDB search no longer misses well-known games buried among their sequels, bundles and DLC (God of War 2005 and Portal 2007 were not offered): it fetches 50 hits plus all (up to 200) games named exactly like the query, shows the best 12 with exact names first, and understands a year in the query (`God of War 2005`, `Portal (2007)`). `sync-igdb` uses the same search, so it never links on a shortened list. All IGDB requests of one process are paced to 4 per second in one place.
- The ranking editor no longer rebuilds the whole board every few seconds while posters are being made (it flashed, and could swallow a tap on a tier name): new posters are swapped in tile by tile.
- Leaving the library and then resizing the window across 600px (or rotating a phone) no longer rewrites the address to `#/library` while another page is shown.
- Changing a game's cover now updates the open game view at once. The cover version has millisecond resolution, and the service worker drops older cached versions of a cover.
- Screenshots (review fixes): decoding is limited by a memory budget (`SCREENSHOTS_DECODE_BUDGET_MB`, default 48) instead of a pixel count, so a large photo can no longer exhaust the Pi's memory; over the budget the original is kept untouched with a thumbnail made by the browser. An upload request is limited to 50 files and 200 parts. Deleting a screenshot while the drive is missing is refused instead of orphaning its files, a start-up sweep never deletes an original (orphans move to `.orphans/`), and listing no longer writes to the drive. The install adds `After=<mount unit>` to the drop-ins and refuses a `SCREENSHOTS_DIR` that is a mount point.
- `deltabacklog backup` no longer migrates the database before copying it, and fails instead of creating and backing up an empty database when `DATA_DIR` is wrong. The Raspberry Pi install writes `app-before-upgrade-<time>.db` before a new version replaces the program.
- Every API error is JSON (`{"error": ...}`), as documented; `/covers/` no longer lists the cover folder.
- The game detail view takes keyboard focus when it opens and gives it back when it closes. With the Theme button set against the system theme, scrollbars and form controls now follow the app's theme.
- Quick add maps the IGDB platform names `NSW` and `PS` the way the IGDB sync does.

## 2026-10-09 (pre-release)

### Security
- Cross-origin POST/PUT/PATCH/DELETE requests are rejected (403) with `http.CrossOriginProtection`; cross-site and same-site `GET /api/*` are rejected too, so other sites cannot trigger lookups.
- JSON write routes under `/api/` require `Content-Type: application/json` (415 otherwise).
- Host allow-list against DNS rebinding (421); extra names via the new `ALLOWED_HOSTS` variable. `/healthz` answers for any host. Error bodies from the guard are JSON (PR #29).

### Added
- **IGDB enrichment**: `deltabacklog sync-igdb --enrich` fills empty fields of linked games and adds time to beat, game modes, perspectives and store links, shown on cards and in the detail view, with a Quick game filter (PR #27).
- Open-source readiness: MIT license, contributing guide, code of conduct, security policy, issue and pull request templates, CI and release workflows, Dependabot configuration (PR #28).
- The friendly address `http://deltabacklog.local` on the Raspberry Pi (mDNS name plus port 80 forwarding), installed by `deploy/install.sh`; manuals, README and screenshots brought up to date (PR #26).
- A demo library (`docs/tools/demo-data`, 40 well-known games, generated placeholder covers or real ones downloaded when keys are set) and a screenshot tool that uses it by default, so the documentation shows no personal data.
- `deltabacklog` knows its version: it is printed in the startup log and in the usage text (`dev` for source builds, the tag for release binaries).
- Release archives include `THIRD_PARTY_LICENSES.txt` with the notices of the Go modules and standard library linked into the binary.
- Rewritten README with quick start, configuration table, backup and restore, FAQ and roadmap.

### Changed
- `GOMEMLIMIT` set in `.env` is now applied (the Go runtime only reads it from the real environment at start-up).
- `cmd/import` no longer defaults to a private NocoDB address; `-nocodb` is empty unless given.
- The documentation screenshots come from the demo library, with real cover art from IGDB and SteamGridDB (illustration only; no cover files are committed).
